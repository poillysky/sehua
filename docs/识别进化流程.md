# 合集识别进化流程（一帖一爬一验）

> **硬约束：** 禁止「先批量重爬再事后抽样」。正确顺序是 **标题分类 → 单帖抓取 → 验收三项准确 → 修解析 → 同帖复验通过 → 下一帖**。  
> 目标：帖子标题、资源子标题（filename）、对应预览图 **三项 100% 准确** 后，才允许扩大该分类的批量。

**适用范围：** 主要针对 `forum_id=2048` 合集/×N 帖；其它论坛可复用同一状态机。  
**代码入口：** `backend/scripts/parse_evolve.py`（分类 / next / run-one / status）  
**解析改动落点：** `backend/parsers/content.py`、`resource_names.py`、`links.py`、`db/persist.py`

---

## 1. 为什么要这样

批量重爬会把「刚用旧逻辑爬过的帖」和「从未修过的帖」混在一起，无法定位是哪一种模板坏了。  
一帖一验能保证：

1. 每个失败都能绑定到 **明确分类（bucket）+ 具体 tid + HTML 样例**；
2. 修完立刻在同帖复验，避免「修了 A 坏了 B」却要等整队跑完才发现；
3. 分类内连续通过后，才对该分类做有限批量，而不是全站一把梭。

---

## 2. 验收三要素（必须全过）

| # | 字段 | 准确含义 | 典型失败 |
|---|------|----------|----------|
| 1 | **帖子标题** `resource_sources.title` / `extract_title` | 去掉站名与板块后缀（如 `\| 最新合集`、论坛名）；不吞正文结构字段 | 标题仍带 `\| 最新合集` |
| 2 | **资源子标题** `ed2k_resources.filename` | 每条磁力/种子有独立正确片名；非帖标题复制；无结构字段污染 | 全员同名、含 `【目录树】`/`导演:`/`购买本帖` |
| 3 | **对应图片** `preview_images`（按 asset） | 多资源时预览集不共享；相邻资源首图不应大面积相同 | `prev_sets=1`、邻接首图雷同 |

单资源合集包（一贴一条大包 magnet）不要求「拆成 N」；×N 合集要求 `n≈磁力数` 且子名/图可区分。

---

## 3. 标题分类（bucket）

按帖标题归类（实现见 `parsers/evolution/classify.py`），例如：

- `tj1221_*`（欧美 / 马克赛 / FC2 / 素人 / 其他）
- `湾搭_*`（中字 / 素人 / 其他）
- `欧美合集` / `亚洲合集` / `动漫合集` / `国产合集` / `FC2合集`
- `有码中字` / `无码合集` / `独家合集` / `其他合集`

**规则：**

- 同一时刻只推进 **一个 bucket**（或用户指定 bucket）。
- 新模板（标题模式未见过）先建新 bucket，再进单帖循环；禁止塞进「其他」后批量盲爬。

---

## 4. 状态机（自我进化）

```text
┌─────────────┐
│ classify    │  从待爬/资源库拉帖 → 打 bucket → 写入进化状态
└──────┬──────┘
       ▼
┌─────────────┐
│ pick next   │  取该 bucket 中 status≠passed 的下一帖（一贴）
└──────┬──────┘
       ▼
┌─────────────┐
│ crawl one   │  抓 HTML（可 replace 入库）→ 落盘 _tmp_evolve_{tid}.html
└──────┬──────┘
       ▼
┌─────────────┐
│ judge       │  验标题 / 子标题 / 预览；写 issues[]
└──────┬──────┘
       ▼
   ok? ──yes──► mark passed → 同 bucket 下一帖
       │
       no
       ▼
┌─────────────┐
│ diagnose    │  对照 HTML 标签（【影片名称】/代号/原文片名…）定位缺口
└──────┬──────┘
       ▼
┌─────────────┐
│ fix parser  │  改 parsers/* + 补单测（用本帖 HTML fixture）
└──────┬──────┘
       ▼
┌─────────────┐
│ re-run same │  同 tid 再 crawl+judge，直到该帖 passed
└─────────────┘
```

**通过标准（分类级）：** 该 bucket 计划集内全部 `passed`，且无未归类失败残留，才算该分类识别逻辑达标。  
**全站 100%：** 所有活跃 bucket 均达标；新帖进队列时先 classify，未知模式开新 bucket 再进化。

---

## 5. Agent / 人工操作约定

1. **先停批量。** 用户说停或逻辑不对时，立刻停 recrawl / 不开连续调度。
2. **入队 ≠ 开爬。** 可把帖子 `requeue` 到 `crawl_pages.pending`，但进化阶段默认 **不开** looping。
3. **严格一帖一帖。** 每次只处理 **1** 个 tid：抓取 → 深挖 HTML 标签/布局 → 验收三项 → 有问题立刻改 `parsers/*` + 单测 → **同帖复验通过** 才结束本轮。  
   - **禁止** `parse_evolve_loop` / `for bucket in …` /「先过 N 帖再回头修」。  
   - **禁止** 为赶进度对多个 bucket 连跑；慢是因为批量盲爬，不是因为一帖深挖。
4. **刚爬过的要识别。** 用进化 state / `updated_at` 区分；失败帖修逻辑后再爬同一帖，不要换帖逃避。
5. **修代码必须带复验。** 每修一处：同帖再 `run-one --tid`；可选再抽 1 个同 bucket 已存 HTML 做离线回归（不新开浏览器）。
6. **文档优先。** 每发现一种新污染/新标签，当场回写本文件「已知模板」与常量注释，再进入下一帖。

## 6. CLI 用法

```bash
cd backend

# 从 2048 待爬/资源库分类，写入状态文件
python scripts/parse_evolve.py classify --forum 2048 --source pending

# 查看各 bucket 进度
python scripts/parse_evolve.py status

# 指定 bucket，取出下一帖（不爬）
python scripts/parse_evolve.py next --bucket 国产合集

# 爬 + 验一帖（可 --hash / --url / --tid）；失败则停，等修解析
python scripts/parse_evolve.py run-one --bucket 国产合集

# 同帖复验（修代码后）
python scripts/parse_evolve.py run-one --tid 1234567 --persist

# 人工确认通过（仅当 judge 偶发误报且已人工核过）
python scripts/parse_evolve.py pass --tid 1234567 --note "人工确认单包合集"
```

状态默认：`backend/data/parse_evolution_state.json`  
单帖 HTML：`backend/_tmp_evolve_{tid}.html`  
单帖报告：`backend/_tmp_evolve_last.json`

## 8. 与现有模块关系

| 模块 | 角色 |
|------|------|
| `parsers/*` | 唯一识别逻辑来源；进化只改这里 + 测试 |
| `workers/recrawl.py` | 单帖 persist 可调用；批量仅在 bucket 达标后 |
| `db/queue.requeue_for_recrawl` | 入待爬；进化期默认不 start crawler loop |
| `crawl_pages` | 队列真相；`pending` 可很大，不等于已验收 |

---

## 9. 完成定义（Definition of Done）

某个 bucket **Done** 当且仅当：

1. 状态文件中该 bucket 目标帖全部 `passed`；
2. 标题 / 子标题 / 预览三项 judge 无 issues；
3. 至少 1 个对应 pytest（或 HTML fixture 回归）覆盖本轮修过的失败模式；
4. 未再对该 bucket 开启「跳过验收的全量重爬」。

全论坛 Done：所有 bucket Done，且待爬新帖能落入已有 bucket 或显式开新 bucket 流程。
