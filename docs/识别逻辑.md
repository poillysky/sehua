# 识别逻辑（现状代码备忘）

> 以仓库**当前实现**为准，不是愿景。改解析时先改代码与单测，再同步本文。  
> 入库落库规则见 [`资源入库模型.md`](./资源入库模型.md)；一帖一验流程见 [`识别进化流程.md`](./识别进化流程.md)。

## 0. 总览：一条链（先名称 / 切块，再认链与卡片）

```text
抓 HTML
  →（可选）下附件 → inject_attachment_text 拼进 HTML
  → parse_thread_content（帖标题 / 帖级预览 / 密码；整帖 meta 仅作初值）
  → 一楼扫名称标签：0～1=单资源，≥2=多资源（此时已有「几条子资源名」）
  → 定抽链楼层：单资源=楼主多楼；多资源=只一楼
  → 在该语料上抽 magnet + ed2k（+ 必要时 115）→ build_assets
  → extract_subresource_blocks：按名称标签把链挂进各资源块
  → 每块 enrich_block_with_cards（名/大小/描述/图）
  → 写回 ParsedAsset → 帖级 meta/desc → judge → persist
```

**顺序锁定：** 先有资源名称（标签），再认磁力/电驴；不是先盲抽全帖链再猜几部片子。

| 阶段 | 主入口 | 职责 |
|------|--------|------|
| 判帖 / 要不要附件 | `workers/thread_outcome.py` | import / stub / need_attachments |
| 正文+链+切块+块卡片 | `parsers/links.py` → `parse_thread_dual` | 产出 `DualParseResult` |
| 子资源切块 | `parsers/content.py` → `extract_subresource_blocks` | 名↔链↔图；块内走 `enrich_block_with_cards` |
| 命名清洗 | `resource_names` + `structure_cards` | 子名候选、禁链内 dn、按结构卡片截尾 |
| 容量字节 | `parsers/magnet.py` → `parse_capacity_bytes` | `13V 66.7GB` / `635V/1.3TB` 等 |
| 验收 | `parsers/evolution/judge.py` | title / filename / preview issues |
| 入库 | `db/persist.py` → `persist_dual_parse` | 按名合并/分行、防抢帖 |

**分工：** 认准「几片子、叫什么、图归谁」是识别层（先切块、块内再卡片）；入库只按识别结果落库（同名并链、异名分行、单资源才挂帖级图、不抢其它帖行）。

## 1. 帖级字段（整帖一份）

来源：`parse_thread_content` / `parse_thread_dual`。

| 概念 | 字段 | 规则摘要 |
|------|------|----------|
| 帖标题 | `DualParseResult.title` → 入库 `resource_sources.title` | **只认列表扫描** `list_title`（`coalesce_thread_title` 列表放第一位）；帖页 subject/正文不再覆盖，避免污染。列表空/「提示信息」才用帖页兜底。仍：去站名后缀；`unwrap_subject_film_title`；未闭合容量 `】` 可补 |
| 帖级描述 | `description` + `metadata` | **主路径：先切资源块，再块内卡片**。块内 `parse_structure_cards`：任意短【标签】开卡，值吃到下一卡；角色靠 stem（名称/大小/类型/有码…）。单资源帖级 meta=唯一块；多资源帖级 meta 清空，明细在各 `asset.description`。板块 profile 只管**展示哪些键**。未知标签只要带分隔也能截断，避免污染片名 |
| 帖级预览 | `preview_images`（≤6） | 主贴图；**仅单资源入库时**可回落到名下 |
| 解压密码 | `extract_password` | **只认标注后的口令**：结构卡 /「解压·提取·资源密码」/「密码：」/「解压用」/「码+98T」。取值经 `clip_password_value`：从标签后吃到换行、下一【标签】、标点、链、附件 UI、空格+中文说明、粘连「才能打开」等为止；**不做**裸 98T 猜测；CF 先还原；「密码错误」等提示词不吞 |

语料范围：

- **先名称、后抽链**：一楼 `【影片/资源名称】` 等标签数决定单/多；**有名称结论之后**再决定扫几层楼、再认 magnet/ed2k。
- **抽链楼层**：单资源（名称 ≤1）→ 楼主多楼（含二楼补链）；多资源（名称 ≥2）→ **只看一楼**。路人回帖默认不参与（标题宣称电驴/求磁力等例外见 `extract_link_corpus_html`）。
- **切块**：同上——单资源 scope 可含楼主多楼；多资源只切一楼；链挂到已有名称块上。
- 附件：下载后 `inject_attachment_text` → 追加 `postmessage_attach0`，再走同一套 `parse_thread_dual`。

## 2. 结构字段与子资源名

### 2.1 资源块 → 块内卡片（主路径）

1. **切资源块**（边界仍靠名称标签 / 布局）：`iter_subresource_title_spans` + `extract_subresource_blocks`。  
   - 0～1 个名称标签 → **1 块**（整段楼主语料；名可回落帖标题/种子名）  
   - ≥2 个名称标签 → **N 块**（每段名称→下一名称/语料尾）  
   - `names_then_links` 等特殊布局沿用现有配对；`pack_attach_fast` 大合集整包 1 块  
2. **块内卡片** `enrich_block_with_cards` → `parse_structure_cards`（`parsers/structure_cards.py`）：  
   - 开括号 + 短标签（≤12 字）+ 闭括号；有角色 stem、或其后带冒号/分隔、或独立成行且本行值较短 → 开新卡；值到下一卡 / magnet / ed2k。  
   - 角色：`name` / `size` / `type` / `coded` / `preview` / `password` / `torrent` / `other`  
   - 写入：`filename`←name（弱名则切段名/种子/帖标题回落）；`size`←容量；其余展示键→`description`；块内图→`preview_images`（≤6）  
3. **资源名**：优先 `role=name`；切块抽出的 `fallback_name` 优先于同块后段【种子名称】，避免串名。

### 2.2 子标题标签（切块边界仍用）

定义：`parsers/resource_names.py` → `SUBRESOURCE_TITLE_MATCH_FORMS`（影片类优先于资源类）。

- **影片类**（优先）：`影片名称代号` / `原文片名` / `影片名称` / `影片名` / `视频名称` …
- **资源类**：`资源名称` / `作品名称` / `套图名称` / `片名` …
- **`【种子名称】` 不是子标题**（role=torrent）；无影片/资源名时可作单资源回落片名。

扫描：`iter_subresource_title_spans`（`content.py`）按文档顺序找标签位置。

取值：`_subresource_title_value` → 标签后到下一结构字段/磁力/结尾；再：

- 去掉粘贴的帖标题行（`_drop_thread_title_lines`）
- 代号类在下一个 `【` 处截断营销文
- `clip_subresource_display_name`：下一结构卡片 / 购买提示等尾巴

入库名最终再经 `resolve_sub_filename`：

1. asset 上已挂的子名（切块写入）  
2. 否则 description 里名称角色（影片类优先；2048 双名互斥时资源名称优先）  
3. 否则帖标题  
4. **绝不用** ed2k/magnet `dn=` 链内技术名

## 3. 资源链位置

`_link_positions_in_scope`：在楼主语料里按出现顺序收集

同 hash 只留**首次**出现。附件注入后的 magnet/ed2k 也算进 scope。

## 4. 切块布局（核心）

入口：`extract_subresource_blocks(html, infohashes, limit_per=6, fallback_title=帖标题)`；装配经 `_assemble_subresource_block` → `enrich_block_with_cards`。

按优先级分支：

### 4.1 无子标题标签

- 0 个名称标签时仍产出块：多链可共名（单资源多码），或按种子名/容量标签区分。
- 名称：块内卡片 /【种子名称】可用则用之，否则回落**帖标题**。
- 预览：看图在磁力前还是后，取相邻窗口 ≤6 张；块内 cards 与图互不跨块。

→ 形态上多为**单资源名**（多名仅当种子名或回落导致不同）；同名多链由入库合并。

### 4.2 连续名称簇 + 下方链接簇（1:1）

判定 `_is_names_then_links_layout`：

- ≥2 个子标题；
- **标题簇内部没有链接**（首标题起 ≤ 位置 < 末标题起）；
- **第一条链接在最后一个标题标签结束之后**。

配对：

| 规则 | 行为 |
|------|------|
| 顺序 1:1 | 名称ᵢ ↔ 第 i 条链 |
| 链多于名 | 多出的链**挂到最后一个已配对名称**（同名多链） |
| 名多于链 | 只配有链的前 N 个 |
| 预览 | 「末名→首链」之间的公共图 + 本链到下一链之间的图，每名 ≤6 |

单测：`tests/test_preview_per_asset.py::test_consecutive_names_then_links_one_to_one`。

### 4.3 交错布局（名称与链穿插）

先 `_detect_magnet_title_layout`：

| 布局 | 含义 | 链归属窗口 |
|------|------|------------|
| `title_then_magnet` | 名称在前（常见 BT 合集） | 本标题起 → 下一标题前 |
| `magnet_then_title` | 链在前（旧样例） | 上一标题结束 → 本标题起 |

每个子标题一段：

- **段内全部** magnet/ed2k 同属该名称（可多链）；
- 字段区（大小/格式/说明）：本标题值后 → 下一标题前；
- 预览：默认从该字段区抠图 ≤6（可显式传 `preview_chunk`）。

单测：`test_segment_multi_link_then_next_name`（名 A 两链 + 名 B 一链）。

### 4.4 块内组装 `_assemble_subresource_block`

对每个 (infohash, name)：

- `size`：`parse_capacity_bytes` 扫字段区（【影片/资源大小】、片名里 `[MP4/899M]`、`13V 66.7GB` 等）
- `format` / `note` / `torrent_name`：结构字段
- `preview_images`：≤ `limit_per`（默认 6）
- `description`：块级【名称/大小/格式/说明】短描述

## 5. 挂回 assets（`links.parse_thread_dual`）

1. 全文语料抽 magnet/ed2k/115 → `build_assets`（115 仅无 magnet/ed2k 时作主链）。  
2. 用全部 magnet/ed2k hash 调 `extract_subresource_blocks`。  
3. 按块顺序写回对应 asset：`filename`、`size`、`preview_images`、`description`；首块 `is_primary`。  
4. 切块未覆盖的 hash **仍保留**（防漏配），接在后面。

## 6. 附件（形态 E）

**触发（正文切块+卡片、试算入库之后；`workers/attach_trigger.py`）：**

| 情况 | 是否下附件 |
|------|------------|
| 正文**无**有效链，但像有附件区（judge `need_attachments` 挂起） | 下（切块后再下；`mode=no_link`） |
| **单资源**正文有链，试算以「**不合格**」开头（含额度不匹配） | **下**（`mode=single_unqual`） |
| **多资源**某块缺链，或整帖试算不合格 | **下**（`mode=multi_missing`；**不做**额度匹配停手） |
| 单资源试算**合格**（额度已匹配） | **不下** |

1. judge 见无链可标 `need_attachments`，但**不立刻下载**；pipeline 先 `parse_thread_dual`（切块+卡片）再 `plan_attachment_fetch`。  
2. 附件轮询：**文件名含 115 / 98 /「一分也是爱」优先**；**文件名含「目录树」硬跳过**（不下、不试算）；其它目录类 txt 排末尾仍纳入。每下一个有链附件即试算：**合格则停**；试算不合格继续下一个。**任一附件命中无权/需登录 → 立即停，整帖 `附件无权（占位入库）`**（勿再试其它附件、勿用部分链误判合格）。单资源：标题 N配额未齐也继续；多资源：`quota_stop=False`，认全链即可。  
3. **附件日限（仅 2048）**：命中「今天下载…请明天再来」→ 入 `attach_queue`（无链先下 / 正文复判均优先报附件侧，勿闷留正文待核）。附件队列每日定时（默认 01:05）排水，单日最多 50 帖。  
4. **空壳种子**：下载返回 HTTP 200 + 附件头但 **body=0** → 跳过，outcome=`种子大小为0`。  
5. 下载 zip/txt/torrent/excel/word → 文本化（含嵌套 rar 逐层）；txt **多段/脏段落后链仍须认全**。浏览器页**无** `cf_clearance` 时可用 **FlareSolverr 同出口**回退（有 clearance 跳过 Flare）；**同帖 Flare 无收获后不再打**。**防卡死/加速**：列表区已明示无权则不下；整帖墙钟约 180s、单附件约 55s；页内 fetch Abort 约 12s；连续空/超时 3 次早停；UI 短等约 8–10s；Flare 约 35s；解压线程限时约 45s；压缩包内链文件名优先、成员/嵌套数封顶；kind 回退去重已试附件名。  
6. `inject_attachment_text` 拼进 HTML。  
7. **再** `parse_thread_dual`：标题/名/大小/图仍以正文为主；**附件块已含目标链时抽链只认附件**。  
8. **附件侧结果优先级**（正文残链复判 / `outcome_from_attach_rejudge_failure`；高→低）：  
   1. 命中「只有特定用户可以下载」等 → **`stub` `附件无权（占位入库）`**（勿落「待核/漏链」）  
   2. 空附件 / Not Found → `附件为空跳过`  
   3. 空壳种子 → `种子大小为0`  
   4. 网络/CF 下不下来 → `retry` `附件下载失败，待重试`  
   5. 抽到可入库链且试算合格 → `成功：附件复判目标链接`；仍不合格才保留正文结果  
9. 单名 → 入库形态 A；多名 → 形态 B。链数原则：**可多不可少**。

**未解析跳过：默认不信，要正证据**（`looks_like_complete_thread_fetch`）：

- 兜底 `未解析到目标链（跳过）` **仅当**本轮抓取证据完整：≥8KB、有一楼正文、有 Discuz/PHPWind 页脚、标题可识别；若有附件区则须已试附件且注入文本足够长。
- 否则（半载/无页脚/CF/提示标题/见附件却无附件区/附件注入过短/证据不足）→ `retry` `页面未完整加载，待重试`，**禁止**因网络异常落成永久跳过。
- 网盘/115sha/无权/空附件等**明确种类**仍按原分支跳过或占位，不走此兜底。

## 7. 容量（形态 D）

`parse_capacity_bytes`（`magnet.py`）：

- 认 `数字 + GB/TB/MB/…` 及短单位；可带片数前缀如 `13V 66.7GB`、`635V/1.3TB`。  
- 字段值可再包装饰括号：`【资源大小】【4.92GB/8V/8配额】`（无冒号）→ `_clip_field_value` 先 `unwrap_decorative_capacity_value` 再截，避免把整段切空。  
- 入库时若 asset.size=0，再扫：块描述、子名、帖标题、`metadata` 的资源/影片大小字段。  
- 「容量不详 / 不明」或不含容量文案 → 允许 size=0（D2/D3）。  
- 有可解析容量文案但库中仍为 0 → 记为 D1 缺口（历史数据靠重爬补写）。

## 8. 入库如何消费识别结果（`persist_dual_parse`）

详见 [`资源入库模型.md`](./资源入库模型.md)。与识别衔接的要点：

1. 只保留与主链同 kind 的资产；hash 去重。  
2. `resolve_sub_filename` 得资源名 → **同名合并**为一组，异名多组。  
3. 截断脏名（短名为长名前缀）→ `_merge_truncated_name_groups` 并入长名。  
4. 每组：`ed2k_links` = 组内全部 URI；`preview_images` ≤6；多组时**不**用帖级预览回填。  
5. 行键：优先空闲/本帖 hash；全被其它帖占用 → `name_row_hash(帖URL, 资源名)`；upsert 拒抢异帖。  
6. `replace_thread_assets`：只保留本次实际写入的 hash；**改判占位**时先写 stub 再清旧真链，使帖子离开不合格明细。  
7. 无链 → stub；有真链后删同帖 stub（非重爬时同帖已有真链不叠 stub）。  
8. **形态标记**：`build_shape_report` → `parse_tags` / `parse_warnings`（见 §13）。

## 9. 进化验收（`evolution/judge`）

对已解析的 `title` + `assets` 查 issues（摘要）：

| issue | 含义 |
|-------|------|
| `title_suffix` / `title_board_suffix` | 标题仍带板块后缀 |
| `empty_assets` | 无资源 |
| `fn_polluted` | 子名含目录树/导演/购买等 |
| `identical_names` | 多链但几乎同一子名 |
| `shared_preview` | 多资源共用同一套非空预览 |
| `adj_same_img` | 邻接首图雷同过多 |
| `many_empty_preview` | 大量空预览 |
| `spans_but_weak_names` | 有子标题跨度但子名区分弱 |
| `filename_copies_title` 等 | 合集子名大量抄帖标题 |

`ok` 仅当 `issues` 为空。流程纪律见 [`识别进化流程.md`](./识别进化流程.md)。

## 10. 形态对照（识别 → 入库）

| 文档形态 | 识别表现 | 入库 |
|----------|----------|------|
| A 单资源 | 无多子标题，或切块后同名；**帖级仅 1 个【资源名称】标签时强制单资源**（2配额=多链，不按 zip 文件名拆行） | 1 行，多链，`ed2k_links`；可回落帖级图 ≤6 |
| B 多资源 | 多子标题且名可区分；交错或 1:1 | M 行；每名自有链/图/大小 |
| C 脏截断名 | 解析偶发短前缀名 | persist 前缀合并成 A |
| D 大小 | 块内/标题容量文案 | 写入字节或允许 0 |
| E 附件链 | inject 后再 parse | 同 A/B |
| F 无链 | assets 空 | stub / 跳过 |

**额度对照（单资源）：** 标题 `N配额` ↔ **正文 plain + 附件文本**的提供链出现次数（不去重；有附件目标链时只计附件）。**不数** HTML/叠语料。有额度时附件轮询扫完再比；**压缩包内多分卷 txt 同样全部合并**（tid=2204368）。辅证：各附件文件名 `Nv` 合计；合计=实链而标题更高 → 虚标软过；合计>实链 → 漏分卷待核。

## 13. 入库形态填槽与对比告警（筛选 / 补规则）

实现：`parsers/resource_frame.py`（定型填槽验收）+ `parsers/shape_report.py`（对外报告 API）；写入 `resource_sources.parse_tags`、`parse_warnings`；`import_outcome` 由填槽 verdict 决定前缀（**不合格绝不以「成功」开头**）。

看帖先判结构（`kind:`）：**单资源** / **多资源** / 无下载链；链数多少不另分形态（记在「链数:N」）。填不上时中文带 **【识别错误】** 或 **【真没有】**，tags 带 `cause:parse` / `cause:missing`。

### 13.1 形态 / verdict tags（可 SQL 筛选）

```sql
-- 单资源
SELECT * FROM resource_sources WHERE parse_tags @> ARRAY['kind:single'];
-- 多资源
SELECT * FROM resource_sources WHERE parse_tags @> ARRAY['kind:multi'];
-- 识别错误导致不合格
SELECT * FROM resource_sources WHERE parse_tags @> ARRAY['cause:parse'] AND parse_tags @> ARRAY['verdict:structure_fail'];
-- 结构不合格
SELECT * FROM resource_sources WHERE parse_tags @> ARRAY['verdict:structure_fail'];
```

| 前缀 | 取值 | 含义 |
|------|------|------|
| `shape:` | `A` / `B` / `C` / `F` | 粗类形态；C 同时带 `shape:A` |
| `kind:` | `single` / `multi` / `no_link` | 帖子结构（两种）；旧库可能仍有 `*_one_link` / `*_multi_link` |
| `verdict:` | `ok` / `structure_fail` / `content_gap` | 填槽验收结果 |
| `cause:` | `parse` / `missing` | 填不上：识别错误 / 真没有 |
| `cap:` | `ok` / `D1` / `D2` / `D3` / `text_present` | 容量类 |
| `src:` | `body` / `attach` | 链是否来自附件 |
| `layout:` | `no_subtitle` / `names_then_links` / … | 切块布局 |
| `links:` / `res:` | `single` / `multi` | 链数、资源名数汇总 |
| `flag:` | `needs_rule` / `link_inconsistent` / `structure_fail` | 告警 / 链数不合规 / 结构硬失败 |

### 13.2 中文提示（`parse_warnings` / outcome）

给人看的文案（示例）：

| 情况 | 提示原文 |
|------|----------|
| 链数对不上 | `【识别错误】链数不合规：识别到100条下载链，入库各子资源合计98条` |
| 标题×N 对不上 | `【识别错误】标题写×5个资源，实际入库2个资源名` |
| 预览串名 | `【识别错误】多资源预览图完全相同…` |
| 帖面无图 | `【真没有】多资源里有…个没有预览图（帖面也无图）` |
| D1 容量 | `【识别错误】有容量文案…但入库大小为0` |

`import_outcome` 示例：

- 正常：`成功：已提取主链 · 形态:单资源 · 链数:3`
- 结构失败：`不合格：预览 · 形态:多资源 · 原因:【识别错误】多资源预览图完全相同…`
- 容量/漏名旁证：`不合格：资源名 · 形态:多资源 · 原因:【识别错误】标题容量…子资源文案合计…`

### 13.3 填槽硬门（结构）

入库前对分组结果：

- **链数合规（硬，识别错误）**：识别 hash 数 == 各组成员数之和 == 各组链接数之和
- **同一模型**：**单资源 = 只有 1 个资源名的多资源**；名数=1 别漏链，名数≥2 别漏资源名  
- **名数=1**：有 `N配额` → 对照实链数（漏链待核）；**仅标题**有配额才对照（标题无配额字样不回落描述脏配额）；**标题 V≈配额** 且 **链 xl/行 size≈标题容量** 才当片数回声（`info:quota_echoes_v`+成功提醒）；容量明显不足（如只入 22/66 且 xl≪标题）仍待核——多半是附件未下全；链数对齐 V 而配额虚高（如 `2V/3配额` 实 2 链）→ `info:quota_over_v_soft`；无配额不强制；链须进组；不做 ×N 切开硬判（标题×N 常为包内片数）；正文**同一名称标签键下**有≥2 个不同取值却只认出 1 名 → `warn:split_collapse_suspect`（嵌套同值 `【影片名称】：【影片名称】：xxx` 不计）；容量不硬判  
- **链数合规键**：磁力按 infohash，ed2k 按完整 URI；勿把同一磁力的 URI 与 hash 计成两条（误报「识别2入库1」）  
- **CF 脏链**：`|file|` 段含 `cdn-cgi` / `email-protection` / HTML 标签的 ed2k 整链丢弃（同 hash 常另有干净副本，如 tid=3486835）  
- **近同名合并**：仅 ⚠ / ⚠️ 差异的双名并入较长名，避免误切多资源  
- **云盘混合配额**（标题含百度/夸克/迅雷/网盘/115网盘等，**不含**纯「115eD2k」电驴标）：配额≠实链 → soft `info:cloud_quota_soft`，outcome 仍「成功」+提醒，不升格「不合格：待核」。纯 115eD2k 且 **V≠配额** 时链数不足 → `title_quota_overclaim_soft` →「不合格：待核」；V≈配额见上，勿待核。
- **提供链数口径**：只数**正文 plain + 附件文本**的出现次数（不去重；同链贴两行算 2）。有附件目标链时只计附件，避免正文样例再叠。**不数** HTML/`blockcode`/抽链叠语料。入库「链数:N」仍是去重后的可入库链。
- **多资源 ×N**：仅 `名数 < 标题×N` 才硬判漏名；`名数 > ×N` → `info:title_count_over_names`（×N 假阳性/包内片数），不结构失败。
- **附件轮询硬规则**：入库试算仍「不合格」时，必须一个一个附件继续判断，直到合格或候选附件全部判完；**单资源**标题配额未齐时即使 outcome 写成「成功」也继续合并；**多资源**不做额度匹配停手（`quota_stop=False`）。
- **附件触发时机**：`need_attachments` 仅挂起；真正下载在切块+结构卡片+试算之后（`attach_trigger.plan_attachment_fetch`）。
- **同 hash 不同文件名**：ed2k 按完整 URI 计份（配额「下载份」）；勿仅按 hash 去重把末条并掉误报漏链（如 tid=3524065）。  
- **名数≥2**：×N/名称标签/每名有链可区分且 ≠ 标题；弱名（过短/占位）=`warn:weak_subresource_name`；分图、文案大小、标题 vs 子文案合计作旁证  
- **短片名**：2～3 字中文或短目录号可保留（`is_acceptable_short_title` / `salvage_short_subresource_name`），勿因 `len<4` 丢段

明细在 persist 返回的 `shape_metrics` / `verdict` / `kind`。
