# sehuatang NAS 全栈部署

> 目标：**PostgreSQL + sehua-app + Search(+scrape-web)** 全部跑在家庭 NAS。  
> 镜像在 **GitHub Actions** 构建并推到 **Docker Hub / GHCR**；NAS **只拉取、不编译**业务镜像。  
> 架构原则见 [架构.md](./架构.md)。本地开发端口见 [本地开发约定.md](./本地开发约定.md)。

---

## 1. 总流程

```text
┌─────────────┐     push      ┌──────────────┐     build/push     ┌─────────┐
│ 开发机      │ ────────────► │ GitHub 仓库  │ ─────────────────► │ Hub/GHCR│
│ 改代码/验证 │               │ + Actions    │                    │ 镜像    │
└─────────────┘               └──────────────┘                    └────┬────┘
                                                                       │ pull
                                                                       ▼
                                                              ┌────────────────┐
                                                              │ 家庭 NAS       │
                                                              │ nas.yml +      │
                                                              │ search.yml     │
                                                              └────────────────┘
```

| 产物 | 镜像名（示例） |
|------|----------------|
| 主栈 app | `poillysky/sehuatang-app`（管理+API 合并） |
| 搜索+刮削 | `poillysky/sehuatang-search`（next-web + scrape-web 合并，自 1.2.5） |
| 数据库 | `postgres:16-alpine`（官方，不自建） |

GHCR 可选：`ghcr.io/poillysky/sehuatang-app` 等。私有仓库需 `docker login`。

## 2. 容器拓扑

两套 Compose（与仓库 `deploy/` 一致）：

```text
  docker-compose.nas.yml              docker-compose.search.yml
  ┌─────────────────────────┐         ┌──────────────────────────┐
  │ postgres :5433          │◄────────│ sehuatang-search         │
  │ sehua-app :8082         │         │   next :3010             │
  └─────────────────────────┘         │   scrape :9209           │
                                      └──────────────────────────┘
         同一 Docker 网络（默认 sehuatang-network）
```

| 服务 | 容器名建议 | 宿主机端口 | 说明 |
|------|------------|------------|------|
| postgres | `sehuatang-postgres` | 5433 | 给本机工具连库；容器互访用主机名 `postgres` |
| app | `sehuatang-app` | **8082** | FastAPI + Playwright + Admin（合并） |
| search | `sehuatang-search` | **3010** + **9209** | Next + scrape 合一；`SCRAPE_ORIGIN=http://127.0.0.1:9209` |

内部连接：

- app → `postgres:5432`
- search（含 scrape）→ 同一资源库（compose 内 `postgres`，或独立资源库端口）
- 浏览器 → `http://NAS_IP:3010`（搜）、`http://NAS_IP:8082`（管）、`http://NAS_IP:9209/health`（刮削）

本机开发仍可用 backend `:8080` + admin `:8081`，以及 `start-search.bat` 分进程起 next/scrape；**勿与生产 8082 混写进运维清单。**

## 3. 推荐目录（NAS）

以飞牛 / 通用 Linux 为例（群晖把前缀换成 `/volume1/...`）：

```text
/vol1/1000/Docker/sehuatang/
├── docker-compose.nas.yml
├── docker-compose.search.yml
├── .env                    # 密码、代理；勿提交 Git
├── data/
│   ├── postgres/           # PG 数据
│   ├── backend/            # cookies、预览图、JWT
│   ├── backups/            # 资源表备份
│   ├── search/             # next-web：p115-config.json
│   ├── search-cache/       # next-web：.next/cache（可丢）
│   └── scrape-covers/      # scrape-web：本地番号封面
├── update.sh               # 主栈一键 pull + up
└── update-search.sh        # 搜索栈一键 pull + up
```

搜索栈为 **合一容器**（`:3010` + `:9209`）：写 `av_metadata`、落盘封面；next-web 经 `/covers` 反代读本机 scrape。详见 `scrape-web/README.md`。

`.env` 最少项：

```bash
POSTGRES_USER=postgres
POSTGRES_PASSWORD=<强密码>
POSTGRES_DB=ed2k
# 论坛出网代理（按需）
# WEB_CRAWLER_PROXY=http://192.168.2.88:7893
GHCR_OWNER=<你的GitHub用户名>
INITIAL_ADMIN_USERNAME=admin
INITIAL_ADMIN_PASSWORD=<改掉默认密码>
```

## 4. Compose 约定（pull 模式）

业务服务**只写 `image:`**，不写 `build:`，确保 NAS 不编译。  
**以仓库 `deploy/docker-compose.nas.yml` 与 `deploy/docker-compose.search.yml` 为准。**

示意：

```yaml
# docker-compose.nas.yml
services:
  postgres:
    image: postgres:16-alpine
    ports: ["5433:5432"]
    shm_size: 1g
  app:
    image: poillysky/sehuatang-app:1.2.28
    ports: ["8082:80"]
    shm_size: 2g
    volumes:
      - ./data/backend:/app/data
      - ./data/backups:/app/data/backups

# docker-compose.search.yml（另文件，共用主栈网络；next+scrape 合一）
services:
  search:
    image: poillysky/sehuatang-search:1.2.8
    ports: ["3010:3000", "9209:9209"]
    environment:
      SCRAPE_ORIGIN: http://127.0.0.1:9209
      SCRAPE_CONFIG_DIR: /data/config
    volumes:
      - ./data/search:/app/data
      - ./data/scrape-covers:/data/covers
      - ./data/scrape-meta:/data/meta
      - ./data/scrape-config:/data/config
```

本机开发仍可用分拆的 backend `:8080` + admin `:8081`（`start.bat`），以及 `start-search.bat` 分进程起 next/scrape；勿当作 NAS 拓扑。

### 持久化对照

| 服务 | 卷 | 丢了会怎样 |
|------|-----|------------|
| postgres | `data/postgres` | **全库没了** |
| app | `data/backend` | 论坛 Cookie、预览图、JWT 等没了；库中资源还在 |
| app | `data/backups` | 资源库单份备份 `ed2k-resources.sql.gz` 没了（库仍在） |
| search | `data/search` | 115 Cookie/目录配置没了，要重填 |
| search | `data/search-cache` | 仅缓存，可忽略 |
| search（scrape） | `data/scrape-covers` | 本地封面没了，可再刮 |
| search（scrape） | `data/scrape-meta` | 本地 meta JSON 没了（库 `av_metadata` 仍在） |
| search（scrape） | `data/scrape-config` | 刮削设置/监控配置没了，要重配 |

> 仓库文件：`deploy/docker-compose.nas.yml`、`deploy/docker-compose.search.yml`、`update.sh`、`update-search.sh`。  
> `ed2k/` 仅本地参考，**不入 Git**。

### Schema 初始化

二选一（推荐 B）：

| 方式 | 做法 |
|------|------|
| A | 空库首次启动时把 `database/migrations/*.sql` 挂进 postgres `initdb.d`（仅**全新库**有效） |
| B | app/backend 启动 lifespan 跑 `ensure_ed2k_schema()` / migrate（与现网一致，**推荐**） |

已有 `ed2k` / `tang98` 数据卷时：**不要**再跑会冲突的 init 脚本，沿用迁移即可。

## 5. 镜像构建与推送（CI）

触发：`main` 分支 push，或手动 `workflow_dispatch`。

```text
.github/workflows/docker-app.yml    → poillysky/sehuatang-app
.github/workflows/docker-search.yml → poillysky/sehuatang-search（及 scrape 镜像按仓库配置）
```

钉版标签见根 `README.md` / `VERSION*`。旧分拆 backend/admin 工作流若仍存在，仅服务于历史镜像，**NAS 以合并 app 为准**。

| 注意 | 说明 |
|------|------|
| 仓库私有 | Package 默认跟随仓库可见性；NAS 用 PAT（`read:packages`）登录 |
| 多架构 | 优先 `linux/amd64`；ARM NAS 再补 `linux/arm64`（Playwright 要额外验证） |
| 构建缓存 | Actions cache；backend 层最重（Chromium） |
| 标签 | 生产可钉 `v1.2.3`，日常用 `latest` |

本地试构建（开发机有 Docker 时）：

```bash
docker build -t sehuatang-backend ./backend
docker build -t sehuatang-admin ./frontend/admin
docker build -t sehuatang-search ./next-web
```

## 6. NAS 一键拉取 / 更新

首次：

```bash
docker login ghcr.io -u <GitHub用户名> -p <PAT>
cd /vol1/1000/Docker/sehuatang
docker compose pull
docker compose up -d
docker compose ps
curl -s http://127.0.0.1:8082/health
```

之后更新（`update.sh`）：

```bash
#!/bin/sh
set -e
cd "$(dirname "$0")"
docker compose -f docker-compose.nas.yml pull
docker compose -f docker-compose.nas.yml up -d
docker image prune -f
echo "OK $(date)"
```

健康检查清单：

| URL | 期望 |
|-----|------|
| `http://NAS_IP:8082/health` | sehua-app OK |
| `http://NAS_IP:8082` | 管理登录页 |
| `http://NAS_IP:3010` | 搜索首页 |
| `http://NAS_IP:9209/health` | scrape-web OK |
| `http://NAS_IP:5433` | （可选）PG 外部工具 |

默认管理账号首次启动后**立刻改密**（`INITIAL_ADMIN_*` 勿用文档默认值长期放公网）。

## 7. 网络与代理

| 场景 | 建议 |
|------|------|
| 仅家庭局域网访问 | 不暴露 8082/3010/9209 到公网；走 NAS 防火墙 |
| 爬虫访问论坛失败 | 设置 `WEB_CRAWLER_PROXY` 指向局域网代理 |
| 管理已同容器反代 | 生产入口即 `:8082`；可选再挂外层 HTTPS |
| 搜索要 HTTPS | 反代 3010，证书用局域网 CA 或 Tailscale |

同域反代示例（逻辑）：

```text
https://nas.local/api/       → app:80（已含管理 SPA）
https://nas.local/           → search:3000   # 或独立子域
https://nas.local/covers/    → scrape-web:9209
```

## 8. 资源与稳定性

| 项 | 建议 |
|----|------|
| 内存 | Docker 可用内存 **≥ 8GB**；同时开爬 + 搜峰值留余量 |
| shm | app **2g**；postgres **1g** |
| CPU | x86 NAS 优先；群晖 ARM 需自测 Chromium |
| 重启策略 | `restart: unless-stopped` 或 `always` |
| 爬虫节奏 | 控制并发与间隔，避免把 NAS 打满、避免触发站点风控 |
| 备份 | 管理后台「数据管理」每日覆盖 `data/backups/ed2k-resources.sql.gz`；整库另可拷 `data/postgres` |

Playwright 在 NAS 上挂掉时优先查：shm 过小、内存 OOM、缺代理、论坛 Cookie 过期。

## 9. 开发 vs 生产

| | 开发机 | NAS 生产 |
|--|--------|----------|
| 主栈 | `start.bat`：backend `:8080` + admin `:8081` | `docker-compose.nas.yml` → app `:8082` |
| 搜索 | `start-search.bat`：next-web `:3010` + scrape-web `:9209` | `docker-compose.search.yml` |
| DB | 常连资源库 `:5435`（见本地开发约定） | compose 内 postgres `:5433` |
| 更新 | 改代码热重载 | `update.sh` / `update-search.sh` pull |

开发不必在 NAS 上挂载源码；**以镜像交付**为准。

### 首次推送到 GitHub

1. 安装 [Git for Windows](https://git-scm.com/download/win)，新开终端确认 `git --version`。  
2. 浏览器登录 GitHub → **New repository**（建议 Private，空仓库不要勾 README）。  
3. 在本机项目根目录：

```powershell
cd Z:\project\sehuatang
git init
git add .
git commit -m "Initial commit: NAS deploy + Docker images"
git branch -M main
git remote add origin https://github.com/<你的用户名>/sehuatang.git
git push -u origin main
```

4. 打开仓库 **Actions**，确认镜像构建成功；Packages 出现 `sehuatang-backend` / `admin` / `search`。  
5. NAS 上按 §6 拉取部署。
