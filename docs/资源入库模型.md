# 资源入库模型（备忘）

> 处理记录按**帖**；入库按**资源名称**。标题文案可重复，帖与「同帖同名」不可重复。

---

## 1. 两层维度

| 层 | 维度 | 唯一键 | 说明 |
|----|------|--------|------|
| **处理记录** | 帖 | `source_url` / tid（`crawl_pages` 等） | **一帖一条**；同一帖不会出现两份 |
| **入库** | 资源名称 | 同帖下每个资源名称一行（`resource_sources` + `ed2k_resources`） | 链、图、大小挂在名称下 |

| 字段 | 层 | 可否重复 |
|------|----|----------|
| `title`（帖标题） | 帖维 | **文案可重复**（不同帖标题字面相同可以） |
| `source_url` / tid | 帖维 | **绝对不可重复**（同一帖只一份） |
| `filename`（资源名称） | 入库维 | 同帖下一名一行；不同帖可撞名 |
| `ed2k_links` | 入库维 | 一名下 1..N 条链 |
| `preview_images` | 入库维 | 一名最多 6 张，名下链共享 |
| `size` | 入库维 | 一名一个；无容量文案或「容量不详」可为 0 |

---

## 2. 帖子形态分类

### A. 单资源帖（常见合集包）

1. 标题：1 个  
2. 资源名称：1 个 → **入库 1 行**  
3. 资源大小：1 个（可从 `【资源大小】：13V 66.7GB`、标题 `【635V/1.3TB】` 等解析）  
4. 图片：最多 6 张，挂在该名称下  
5. 链接：1 组（1..N 条 magnet / ed2k），全在该行 `ed2k_links`，共享上述图与大小  

### B. 多资源帖

1. 标题：1 个（同帖多行共用）  
2. 资源名称：M 个（彼此可区分）→ **入库 M 行**  
3. 资源大小：每个名称各自 1 个  
4. 图片：每个名称各自最多 6 张（**不跨名称共享**）  
5. 链接：每个名称各自 1 组（该名下 1..N 条）  

### C. 单资源但识别出多名（应收成 A）

- 正文实质只有 1 个资源名，附件多链；或夹带**截断脏名**（完整名的前缀）  
- **应合并为 A**：1 名称、1 行、多链、帖级预览 ≤6、容量按正文/标题  

### D. 大小缺失（结构仍按 A/B）

| 子类 | 条件 | size |
|------|------|------|
| D1 | 标题/描述/名称含 GB·TB·MB 等容量 | **应写入**字节 |
| D2 | 写明「容量不详 / 不明」 | 允许 0 |
| D3 | 全文无容量信息 | 允许 0 |

### E. 链来自附件

- 标题 / 资源名 / 大小 / 图：来自帖正文  
- 链接：来自 zip / txt 等附件  
- 单名 → A；多名 → B  

### F. 无可用下载链

- 无 magnet / ed2k（或仅网盘、115sha 等应跳过类型）  
- → 跳过或 stub，**不**按多链合集入库  

---

## 3. 硬约束（验收口诀）

1. **帖唯一**：同一 `source_url` / tid 不会有两份处理记录。  
2. **标题可撞名**：不同帖 `title` 字面相同允许。  
3. **一名一行**：同帖同资源名称不得拆成多行（多链进 `ed2k_links`）。  
4. **图按名**：单资源整帖 ≤6 张共享；多资源每名 ≤6 张且不串名。  
5. **条数 = 资源名称数**，不是磁力条数。  
6. **禁止**用 hash 条数当入库行数；合集主 hash 不得抢走其它帖的 `source_url` 行。

## 3.1 填槽框架与验收 verdict

实现：`parsers/resource_frame.py`（`persist` 入库前调用）。流程：**先判结构（单/多资源）→ 按模板填槽 → 硬门验收**。

### 帖子结构（只有两种）

**同一模型：** 按「资源名」切块挂链；**单资源 = 只有 1 个资源名的多资源**（名数=1），多资源 = 名数≥2。差别只在名数门控，不是两套形态。

| kind | 中文 | 要点 |
|------|------|------|
| `single` | 单资源 | 名数=1；链数记在 outcome「链数:N」/ metrics（可 1 链或多链） |
| `multi` | 多资源 | 名数≥2；每名可 1 链或多链 |
| `no_link` | 无下载链 | stub / 不按合集入库 |

粗类 A/B/C/F 仍写入 `shape:*`（兼容）；结构写入 `kind:single` / `kind:multi`。附件来源用 `src:attach`。旧细类 `*_one_link` / `*_multi_link` 读库时仍映射为单/多资源文案。

### 填不上时归因

| cause | 中文前缀 | 何时 |
|-------|----------|------|
| `parse` | 【识别错误】 | 帖面有线索（×N、容量文案、名称标签、帖级预览）却没填对 / 链数对不上 / 预览串名 / 容量合计不符 |
| `missing` | 【真没有】 | 模板允许空，且帖面也无对应数据（如 D3 无容量、帖面无图） |

### 图片 / 容量验收

| 槽位 | 模板要求 | 不合格时 |
|------|----------|----------|
| 预览 | 单资源整帖 ≤6 共享；多资源每名 ≤6 且不串名 | 串名 / 帖有图未按名分配 → `structure_fail` + `flag:preview_fail`（漏资源名旁证）；帖面也无图 → 【真没有】软提醒 |
| 容量 | 多资源：标题 vs 各子资源文案合计（不从链接算）；单资源不硬判 | 不一致 → 漏资源名旁证硬门 |

| verdict | 含义 | `import_outcome` |
|---------|------|------------------|
| `ok` | 结构槽位按模板填满 | 以 **`成功：`** 开头 |
| `structure_fail` | 结构硬门失败（含预览硬失败） | 以 **`不合格：…`** 开头（禁止「成功」） |
| `content_gap` | 容量类（历史/旁路） | 以 **`不合格：容量`** 开头（禁止「成功」） |

不合格**仍写入**（便于筛、对照、重爬），靠 `parse_tags` 含 `kind:…` / `verdict:…` / `cause:parse|missing` / `flag:structure_fail` 发现。

**禁止假成功（硬门补充）：**

- **同一模型**：单资源 = 名数=1 的多资源；名数=1 别漏链，名数≥2 别漏资源名  
- **名数=1**：有 `N配额` 才核链数（漏链→待核）；资源名可=标题；不做 ×N 切开硬判；容量不硬判；正文同名标签≥2 却只认出 1 名 → `warn:split_collapse_suspect`（多资源漏切成单名 → **不合格：资源名**）  
- **名数≥2**：名须切全、可区分、每名有链；弱名硬判；分图/文案大小/标题↔子文案合计作漏名旁证  
- 管道对外 `outcome` 以入库 `import_outcome` 为准  
- 占位 stub 若传入「成功…」会改写成「占位：…」

## 4. 与表字段对应

| 概念 | 主要字段 |
|------|----------|
| 帖 URL | `resource_sources.source_url` |
| 帖标题 | `resource_sources.title` |
| 资源名称 | `ed2k_resources.filename` |
| 主链 / 行键 | `resource_sources.hash` ↔ `ed2k_resources.hash`（优先用不被其它帖占用的 hash） |

| 名下预览 | `resource_sources.preview_images[]`（≤6） |
| 名下大小 | `ed2k_resources.size` |
| 形态/告警标记 | `resource_sources.parse_tags[]` / `parse_warnings[]`（见 [`识别逻辑.md`](./识别逻辑.md) §13） |
