# 本地开发约定

## 两套项目完全独立（必记）

仓库里是 **两套独立产品**，只是共用 **资源库**（常见 `RESOURCE_POSTGRES_*` / `5435` / `ed2k`），进程、启动脚本、配置互不绑定：

| 项目 | 目录 | 本地端口 | 启动 | 职责 |
|------|------|----------|------|------|
| **爬虫管理** | `backend/` + `frontend/admin/` | API **8080** · Admin **8081** | `start.bat` | 论坛爬取、入库、运维后台 |
| **搜索/刮削** | `next-web/` + `scrape-web/` | 搜索 **3010** · 刮削 **9209** | `start-search.bat` | 检索浏览、番号刮削与封面 |

**约定：**

- 开搜索/刮削时 **不要** 顺手开爬虫管理；开爬虫管理时 **不要** 顺手开 next-web/scrape。
- 用户说「启动 next-web」= 只开 `next-web` + 需要时的 `scrape-web`；说「管理/爬虫」= 只开 `backend` + `admin`。
- 两边互不依赖对方进程；联调靠共享库表与文件（见下表），不是靠同机一起起服务。

## 服务与端口

| 服务 | 目录 | 端口 | 启动 |
|------|------|------|------|
| backend API | `backend/` | **8080** | `start.bat` 或 uvicorn |
| admin | `frontend/admin/` | **8081** | `start.bat` 或 `npm run dev` |
| next-web 搜索 | `next-web/` | **3010** | `start-search.bat` |
| scrape-web 刮削 | `scrape-web/` | **9209** | `start-search.bat`（一并启动） |

产线 NAS：管理合并入口 **8082**，搜索 **3010**，Postgres 宿主机 **5433**，scrape-web **9209**。见 [部署.md](./部署.md)。

## PostgreSQL（本地常见）

| 用途 | 端口（本机常见） | 库名 | 谁连 |
|------|------------------|------|------|
| 资源库 / 搜索 / 刮削元数据 | **5435** | `ed2k` | next-web、scrape-web、`RESOURCE_POSTGRES_*` |
| 爬虫侧独立库（若启用） | **5436** | 见 `backend/.env` 的 `POSTGRES_*` | backend 主连接 |
| NAS Compose 映射 | **5433**→容器 5432 | `ed2k` | 产线 |

本地改端口时，请同步：`next-web/.env.local`、`scrape-web/.env`、`backend/.env` 的 `RESOURCE_POSTGRES_PORT`，以及本文件与 bat 提示文案。

## 共享表（契约摘要）

| 表 | 写入方 | 读取方 |
|----|--------|--------|
| `ed2k_resources` / `resource_sources` | backend（爬虫管理） | next-web |
| `av_metadata` / `av_scrape_queue` | scrape-web | next-web（封面合并、女优搜、刮削设置） |
| 封面文件 | scrape-web `data/covers` | next-web 经 `/covers` rewrite → scrape-web |

番号板块配置：`next-web/config/boards.ts`；刮削 kind/优先级：`scrape-web` config。变更任一侧时核对另一侧是否需同步。
